
**新狀況 A:停止時出現「停止逾時:背景執行緒尚未結束」。**
看 log,按停止後隔了幾秒才印出這行 ERROR。意思是:CLI 為了不再用 `os._exit()` 硬關,改成「正常地叫背景執行緒停下來」,但**某個背景執行緒沒有在時限內乖乖結束**,所以觸發了逾時警告。app 沒被關掉(好),但停止流程並不乾淨——有執行緒卡住沒收好。

**新狀況 B:音訊破音(原本不破)。**
這是這次改動的**副作用**,而且很可能跟 A 同源。我的判讀:CLI 為了讓執行緒能被叫停,可能改了串流迴圈或緩衝的處理方式(例如加了會週期性檢查「該停了嗎」的邏輯、或動到讀取/送出的節奏),結果影響到串流期間的資料流暢度,造成破音。原本「無 delay 且不破」,現在「無 delay 但破音」——延遲沒變差,但資料連續性被打亂了。
